1. บทบาทในทีม

ทุกคนต้องเขียนโค้ดได้ แต่ควรมี "ความถนัดหลัก" ที่ไม่ทับกันมาก เพื่อแบ่งโจทย์ได้เร็ว

บทบาทหน้าที่ถนัดหัวข้อ (ตัวอย่าง)
Coder หลักพิมพ์เร็วและแม่น ตั้ง template ตอนเริ่ม ทำข้อง่ายข้อแรกimplementation, data structures
Thinkerอ่านโจทย์เยอะ คิด solution บนกระดาษจนพร้อมพิมพ์DP, math, greedy
Scout / debuggerดู scoreboard หาข้อที่ทีมอื่นทำได้ ตรวจโค้ดจาก printout เขียน brute forcegraph, geometry, strings
กฎเครื่องเดียว
  • ขึ้นเครื่องเมื่อคิดเสร็จแล้วเท่านั้น — เขียน pseudo-code หรือโครงหลักบนกระดาษก่อน
  • Debug เกิน 5–10 นาที → print โค้ด แล้วลุกให้คนอื่นใช้เครื่อง ไปไล่บนกระดาษ
  • คนที่ไม่ได้อยู่หน้าเครื่องต้องทำอย่างใดอย่างหนึ่งเสมอ: คิดข้อถัดไป, เขียน test case, หรือตรวจโค้ด
  • พูดออกเสียงทุกครั้งที่ submit และผลที่ได้ เพื่อให้ทุกคนรู้สถานะ (เขียนบนกระดาษรวมด้วยว่าข้อไหน AC/WA/ใครถือ)

2. แผน 5 ชั่วโมง

ช่วงเวลาสิ่งที่ทำ
0–5 นาทีCoder พิมพ์ template + script compile/stress; อีกสองคนแบ่งโจทย์ (คนละครึ่ง) อ่านหาข้อง่าย
5–60 นาทีทำข้อง่ายทั้งหมดให้เร็วที่สุด — ข้อง่ายที่ AC ช้า 30 นาที เสีย penalty เท่ากับ WA 1.5 ครั้ง ดู scoreboard ว่าข้อไหนคนอื่นผ่านเร็ว
1–4 ชั่วโมงทำข้อกลางตามลำดับจำนวนทีมที่ผ่านใน scoreboard ทุกข้อที่จะพิมพ์ต้องมีคนอย่างน้อยสองคนเห็นด้วยกับ solution
ชั่วโมงสุดท้าย (scoreboard freeze)เลือกข้อที่ใกล้ AC ที่สุด 1–2 ข้อแล้วทุ่มทั้งทีม อย่าเริ่มข้อใหม่ที่ยาวเกิน 45 นาที
15 นาทีสุดท้ายส่งทุกอย่างที่ "อาจผ่าน" — WA ไม่มีค่าปรับถ้าข้อนั้นไม่ผ่าน
ติดหล่มถ้าข้อหนึ่งใช้ไปเกิน 60 นาทีโดยไม่ใกล้ขึ้นเลย และยังมีข้อที่ทีมอื่นผ่านเยอะแต่ทีมเรายังไม่ได้ ให้เปลี่ยนคนหรือเปลี่ยนข้อ — sunk cost เป็นศัตรูอันดับหนึ่งของ ICPC

3. อ่านโจทย์ & เลือกข้อ

  • อ่าน input/output + constraint + sample ก่อนเรื่องราว — บอกระดับความยากได้เร็ว
  • ข้อที่ statement สั้น, ตัวอย่างเยอะ, constraint เล็ก มักง่าย · ข้อที่มีภาพเรขาคณิตหรือ interactive มักถูกทิ้ง
  • เขียนสรุปโจทย์ 2–3 บรรทัดบนกระดาษ (เป็นคณิตศาสตร์ ไม่ใช่เรื่องราว) แล้วส่งต่อให้เพื่อนได้ทันที
  • ก่อนพิมพ์ ลองกับ sample ด้วยมือว่า solution ให้คำตอบถูก
  • scoreboard คือข้อมูลชั้นดี: ข้อที่หลายทีมผ่านภายใน 30 นาที = ง่าย แม้อ่านแล้วดูยาก

4. Checklist ก่อน submit (ใช้ 30 วินาที ประหยัด 20 นาที)

  • ผ่าน sample ทุกตัว และ test มือ: n = 1, n สูงสุด, ค่าเท่ากันหมด, ค่าติดลบ/ศูนย์
  • ไม่มี overflow (ผลคูณ, ผลรวม, INF + w)
  • หลาย test case: reset ตัวแปรทุกตัว
  • ขนาด array พอ (+5), ไม่มี index −1
  • Output format ตรงตัวอักษร (ตัวพิมพ์, ช่องว่าง, "Case #x:") และลบ debug output แล้ว
  • Complexity กับ n สูงสุดผ่าน budget (ลองรัน input ขนาดใหญ่ที่สร้างเอง)

5. เมื่อโดน WA / TLE / RTE

  1. อ่านโจทย์ใหม่ทั้งหมด (ให้เพื่อนอ่านด้วย) — WA จำนวนมากมาจากเข้าใจโจทย์ผิด
  2. ไล่ checklist ด้านบนอีกครั้ง
  3. เขียน brute force แล้ว stress test (ด้านล่าง)
  4. RTE: array เกิน, recursion ลึก, หาร 0, ใช้ *s.begin() ตอน set ว่าง
  5. TLE: endl/ไม่ได้ปิด sync, ส่ง vector by value ใน recursion, map ในลูปที่ใช้ array ได้, Dijkstra ไม่มี if (d != dist[v]) continue

6. Stress testing

สามไฟล์: sol.cpp (ที่ต้องการทดสอบ), brute.cpp (ช้าแต่ถูกแน่), gen.cpp (สุ่ม input ขนาดเล็ก) — test เล็กจะทำให้ debug ง่าย

// gen.cpp — seed มาจาก argument เพื่อให้ทำซ้ำได้
#include <bits/stdc++.h>
using namespace std;
int main(int argc, char **argv) {
    mt19937 rng(atoi(argv[1]));
    auto rnd = [&](int l, int r) { return (int)(rng() % (r - l + 1)) + l; };
    int n = rnd(1, 8);
    cout << n << '\n';
    for (int i = 0; i < n; i++) cout << rnd(1, 10) << " \n"[i == n - 1];
}
# stress.sh  (Linux / WSL — environment วันแข่งเป็น Linux)
g++ -O2 -o sol sol.cpp && g++ -O2 -o brute brute.cpp && g++ -O2 -o gen gen.cpp || exit 1
for i in $(seq 1 2000); do
    ./gen $i > in
    ./sol < in > out1
    ./brute < in > out2
    if ! cmp -s out1 out2; then
        echo "Mismatch on seed $i"; cat in; echo "sol:"; cat out1; echo "brute:"; cat out2
        exit
    fi
done
echo "All passed"

ซ้อมพิมพ์ script นี้จนทำได้ใน 2 นาที — ในวันแข่งไม่มีไฟล์ของคุณ (ยกเว้นใน notebook ที่พิมพ์มา)

9. วันแข่ง

  • วันก่อนหน้า: ไม่เรียนของใหม่ นอนให้พอ เตรียม notebook ฉบับพิมพ์, บัตร, นาฬิกา (ถ้าอนุญาต)
  • Practice session: ทดสอบ compiler, editor, การ print, การ submit, ความเร็วของ judge (ส่งโค้ด loop 108 ดูเวลา), stack limit (recursion ลึก 106)
  • ตกลงกันอีกครั้ง: ใครอ่านข้อไหน ใครพิมพ์ template
  • ระหว่างแข่ง: กินน้ำ/ขนม ไม่โทษกันเมื่อ WA — สถานการณ์ตึงเครียดทำให้ทีมพลาดมากกว่าความรู้ที่ขาด
