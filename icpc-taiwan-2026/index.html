ICPC Asia Taiwan Regional 2026

Roadmap: จาก "รู้จัก algorithm" ถึง "พร้อมลงสนาม ICPC"

ชุดบทเรียน 9 หน้า เรียงตามลำดับที่ควรเรียน แต่ละหน้ามีคำอธิบาย, โค้ด C++ ที่เอาไปใส่ team notebook ได้, ข้อควรระวัง และรายการโจทย์ที่ติ๊กเก็บความคืบหน้าได้ (บันทึกในเบราว์เซอร์นี้)

ICPC Regional ต่างจากการแข่งที่เคยทำยังไง

เรื่องรายละเอียดผลต่อการเตรียมตัว
ทีม3 คน ใช้คอมพิวเตอร์เครื่องเดียวเวลาพิมพ์เป็นทรัพยากรที่แย่งกัน — ต้องคิดบนกระดาษให้จบก่อนขึ้นเครื่อง
เวลา5 ชั่วโมง, โจทย์ประมาณ 10–13 ข้อ (ภาษาอังกฤษ)อ่านเร็ว, แบ่งโจทย์กันอ่าน, รู้ว่าข้อไหนควรทิ้ง
คะแนนเรียงตามจำนวนข้อที่ผ่าน แล้วจึงดู penalty = ผลรวมนาทีที่ผ่านแต่ละข้อ + 20 นาทีต่อ wrong submission (นับเฉพาะข้อที่ผ่านในที่สุด)ข้อง่ายต้องผ่านเร็วและไม่พลาด — submit ผิดแพงกว่าที่คิด
ผลตัดสินได้แค่ Accepted / Wrong Answer / TLE / RTE ฯลฯ ไม่มี partial score, ไม่เห็น testต้องหา bug เองด้วย test ที่คิดเองและ stress test
เอกสารส่วนใหญ่อนุญาต team notebook แบบพิมพ์ (มักจำกัด 25 หน้า A4) ห้ามอินเทอร์เน็ตเตรียม notebook ของทีมตั้งแต่ตอนนี้ — ทุกหน้าในชุดนี้มีโค้ดที่ควรใส่
เช็คกฎจริงของปีนี้วันแข่ง สถานที่ (Taiwan regional หมุนเวียนระหว่างมหาวิทยาลัยหลายแห่ง) จำนวนหน้าของ notebook ภาษาที่อนุญาต และ compiler flags ให้ดูจากประกาศของ regional บน icpc.global และเว็บของผู้จัดปีนั้น — ตัวเลขด้านบนเป็นค่าทั่วไปของ ICPC Asia regional

"พร้อมขั้นพื้นฐาน" หมายถึงอะไร

ใน regional ของเอเชีย ทีมที่เตรียมตัวดีระดับพื้นฐานควรทำข้อง่ายทุกข้อได้ภายใน 1–2 ชั่วโมงแรกโดยไม่ WA และมีโอกาสได้ข้อระดับกลางอีก 1–3 ข้อ ข้อเหล่านั้นเกือบทั้งหมดมาจากเครื่องมือในชุดนี้:

  • Implementation / simulation ที่ต้องเขียนให้ถูกในครั้งเดียว
  • Sorting + greedy, binary search on answer, two pointers, prefix sums
  • DP มาตรฐาน (knapsack, LIS, grid, interval, bitmask เล็กๆ)
  • Graph: BFS/DFS, Dijkstra, DSU/MST, topological sort, SCC เบื้องต้น
  • Tree: DFS order, LCA, tree DP; Data structures: Fenwick, segment tree (+lazy)
  • Math: modular arithmetic, sieve, gcd, nCr mod p
  • String: hashing, KMP/Z; Geometry: cross product, convex hull

หัวข้อขั้นสูง (flow ซับซ้อน, FFT, suffix automaton, HLD, CHT ฯลฯ) มีกล่าวถึงเป็น "ภาคต่อ" เท่านั้น — ถ้ายังทำโจทย์ "ต้องทำ" ในชุดนี้ไม่ครบ อย่าเพิ่งไปถึงตรงนั้น

วิธีใช้ชุดนี้

  1. อ่านหัวข้อ ให้เข้าใจ "สังเกตยังไงว่าโจทย์ใช้เทคนิคนี้" มากกว่าจำโค้ด
  2. พิมพ์ template เองจากความเข้าใจ (อย่า copy) แล้วใช้ทำโจทย์ข้อแรกของหัวข้อ — template ที่ผ่าน AC แล้วค่อยใส่ notebook
  3. ทำโจทย์ที่ติดป้าย ต้องทำ ให้ครบ ข้อที่เหลือทำเมื่อมีเวลา ข้อ ท้าทาย คือระดับกลางของ regional
  4. ติดเกิน 40–60 นาทีโดยไม่มีไอเดียใหม่ → อ่าน hint/editorial แล้วเขียนเองใหม่ทั้งหมด จด "ไอเดียที่พลาด" ไว้หนึ่งบรรทัด
  5. ทุกสัปดาห์ทำ mock contest ทั้งทีม (ดูหน้า 09) — ทักษะทีมฝึกจากการทำโจทย์คนเดียวไม่ได้
โจทย์ที่มีป้าย มีใน repo แล้ว คือข้อที่มีไฟล์ใน cses/ ของ repo นี้ จึงติ๊กไว้ให้ก่อน — ถ้ายังไม่ AC จริงก็เอาติ๊กออกได้

ทำเฉพาะข้อ ต้องทำ ในหน้า 02, 03, 04, 05 (ส่วน DSU/Dijkstra/Fenwick/segment tree) และ 06 (mod/sieve/nCr) ข้าม 07–08 ไปก่อนยกเว้น string hashing กับ cross product แล้วใช้เวลาที่เหลือกับ mock contest อย่างน้อย 2 ครั้งและทำ notebook — การได้ข้อง่ายครบเร็วสำคัญกว่าการรู้หัวข้อเพิ่มอีกหนึ่งเรื่อง

Checklist ความพร้อมก่อนวันแข่ง

  • เขียน BFS, Dijkstra, DSU, Fenwick, segment tree (lazy) ได้จากความจำภายใน 10 นาทีต่ออัน และผ่าน AC
  • ทำ CSES ข้อ "ต้องทำ" ครบทุกหน้า
  • ทำ mock contest 5 ชม. ทั้งทีมแล้วอย่างน้อย 4 ครั้ง และทบทวนหลังแข่งทุกครั้ง
  • ทำชุดโจทย์ ICPC Asia regional ย้อนหลัง (Taiwan หรือ regional อื่นในเอเชีย) แล้วอย่างน้อย 2 ชุด
  • Team notebook พิมพ์แล้ว ทุกโค้ดในนั้นเคยผ่าน AC และมีสารบัญ
  • มี script stress test (brute vs solution) ที่ใช้ได้ทันที
  • ทีมตกลงบทบาทและกติกาการใช้เครื่องแล้ว (ใครพิมพ์ เมื่อไหร่ต้องลุก, ใครดู scoreboard)
  • ซ้อมกับ environment แบบวันแข่ง (Linux, editor ที่มีให้, ไม่มี autocomplete/AI/internet)
