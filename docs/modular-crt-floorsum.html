Modular Arithmetic, CRT และ Floor Sum

บทเรียนสำหรับ competitive programming ตั้งแต่พื้นฐานไปจนถึงเทคนิคที่ใช้ใน AtCoder / Codeforces โค้ดทุกชิ้นเป็น C++17 และผ่านการทดสอบกับ brute force แล้ว

อิงเนื้อหาหลักจาก cp-algorithms AtCoder Library (floor_sum, crt) มีเครื่องคิดเลขให้ลองเล่น

1Modular arithmetic

นิยาม เราเขียน $a \equiv b \pmod m$ (อ่านว่า a สมภาค b มอดุโล m) เมื่อ $m \mid (a-b)$ หรือก็คือ $a$ และ $b$ เหลือเศษเท่ากันเมื่อหารด้วย $m$

มองง่าย ๆ: เรากำลังทำงานบน "นาฬิกา" ที่มี $m$ ช่อง คือ $\{0,1,\dots,m-1\}$ ทุกการบวก ลบ คูณ จะวนกลับมาในช่วงนี้เสมอ

1.1 กฎพื้นฐาน

$$ \begin{aligned} (a+b) \bmod m &= ((a \bmod m) + (b \bmod m)) \bmod m\\ (a-b) \bmod m &= ((a \bmod m) - (b \bmod m) + m) \bmod m\\ (a\cdot b) \bmod m &= ((a \bmod m)\cdot(b \bmod m)) \bmod m \end{aligned} $$

แต่ การหาร ไม่ทำแบบนี้ได้ตรง ๆ: $\frac{a}{b} \bmod m \ne \frac{a \bmod m}{b \bmod m}$ ต้องใช้ modular inverse แทน

กับดักที่เจอบ่อย
  • เศษติดลบ: ใน C++ -7 % 3 == -1 ไม่ใช่ 2 ให้ใช้ ((a % m) + m) % m
  • Overflow ตอนคูณ: ถ้า $m \approx 10^9$ ผลคูณสองตัวได้ $\approx 10^{18}$ ยังพอดีกับ long long แต่ถ้า $m \approx 10^{18}$ ต้องใช้ __int128
  • ลืม mod หลังลบ: (a - b) % m อาจติดลบ ให้บวก m ก่อน

1.2 Binary exponentiation — คำนวณ $a^e \bmod m$ ใน $O(\log e)$

ใช้ข้อเท็จจริงว่า $a^{e} = (a^{e/2})^2$ ถ้า $e$ คู่ และ $a^e = a\cdot a^{e-1}$ ถ้า $e$ คี่ หรือเขียนแบบวนลูปตามบิตของ $e$

using ll = long long;
ll binpow(ll a, ll e, ll m) {
    ll r = 1 % m;  a %= m;  if (a < 0) a += m;
    while (e) {
        if (e & 1) r = (__int128)r * a % m;
        a = (__int128)a * a % m;
        e >>= 1;
    }
    return r;
}

1.3 Extended Euclidean algorithm

นอกจากหา $g=\gcd(a,b)$ แล้ว ยังหา $x,y$ ที่ทำให้ $ax+by=g$ (Bézout's identity) ได้ด้วย เป็นเครื่องมือหลักของทั้ง inverse และ CRT

แนวคิด: ถ้ารู้ $x_1,y_1$ ที่ $b x_1 + (a \bmod b) y_1 = g$ แล้ว เพราะ $a \bmod b = a - \lfloor a/b\rfloor b$ จะได้

$$x = y_1,\qquad y = x_1 - \left\lfloor \tfrac{a}{b} \right\rfloor y_1$$ 
ll exgcd(ll a, ll b, ll &x, ll &y) {
    if (b == 0) { x = 1; y = 0; return a; }
    ll x1, y1;
    ll g = exgcd(b, a % b, x1, y1);
    x = y1;
    y = x1 - (a / b) * y1;
    return g;
}

ค่า $|x|,|y|$ ที่ได้จะไม่เกิน $\max(a,b)$ จึงไม่ overflow

1.4 Modular inverse

นิยาม $a^{-1}$ คือจำนวน $x$ ที่ $a x \equiv 1 \pmod m$ มีอยู่ ก็ต่อเมื่อ $\gcd(a,m)=1$

วิธีที่ 1: Extended Euclid (ใช้ได้ทุก $m$ ที่ $\gcd(a,m)=1$)

หา $x,y$ ที่ $ax+my=1$ แล้ว mod ทั้งสองข้างด้วย $m$ ได้ $ax\equiv 1$

ll inv_mod(ll a, ll m) {           // คืน -1 ถ้าไม่มี inverse
    ll x, y;
    ll g = exgcd(((a % m) + m) % m, m, x, y);
    if (g != 1) return -1;
    return ((x % m) + m) % m;
}

วิธีที่ 2: Fermat's little theorem (เมื่อ $m=p$ เป็นจำนวนเฉพาะ)

$$a^{p-1}\equiv 1 \pmod p \;\Rightarrow\; a^{-1}\equiv a^{p-2} \pmod p$$

เขียนสั้นสุด: binpow(a, p - 2, p) ทั่วไปกว่านี้คือ Euler: $a^{-1} \equiv a^{\varphi(m)-1}$

วิธีที่ 3: inverse ของ $1..n$ ทั้งหมดใน $O(n)$

จาก $m = \lfloor m/i \rfloor \cdot i + (m \bmod i)$ จะได้

$$i^{-1} \equiv -\left\lfloor \tfrac{m}{i} \right\rfloor \cdot (m \bmod i)^{-1} \pmod m$$ 
inv[1] = 1;
for (int i = 2; i <= n; i++)
    inv[i] = (m - (m / i) * inv[m % i] % m) % m;
ใช้บ่อยมาก คำนวณ $\binom{n}{k} \bmod p$: เตรียม fact[] และ invfact[] ไว้ก่อน แล้วตอบแต่ละ query ใน $O(1)$ ด้วย $\binom{n}{k} = n!\,(k!)^{-1}((n-k)!)^{-1}$

1.5 Linear congruence $ax\equiv b \pmod m$

ให้ $g=\gcd(a,m)$

  • ถ้า $g \nmid b$ ⇒ ไม่มีคำตอบ
  • ถ้า $g \mid b$ ⇒ หารทุกตัวด้วย $g$: $a'x \equiv b' \pmod{m'}$ โดย $a'=a/g,\ b'=b/g,\ m'=m/g$ ตอนนี้ $\gcd(a',m')=1$ จึงได้ $x \equiv b'\cdot a'^{-1} \pmod{m'}$ (มี $g$ คำตอบในช่วง $[0,m)$)

สมการนี้คือ "CRT ที่มีแค่สมการเดียว" และเป็นแกนของการรวมสองสมการในหัวข้อถัดไป

2Chinese Remainder Theorem (CRT)

ปัญหาโบราณจากตำรา Sunzi Suanjing: "มีของจำนวนหนึ่ง นับทีละ 3 เหลือ 2 นับทีละ 5 เหลือ 3 นับทีละ 7 เหลือ 2 ของมีกี่ชิ้น?" ซึ่งคือการแก้ระบบ

$$x\equiv 2 \pmod 3,\quad x\equiv 3 \pmod 5,\quad x\equiv 2 \pmod 7$$

คำตอบคือ $x \equiv 23 \pmod{105}$

2.1 ตัวทฤษฎีบท

ทฤษฎีบท ให้ $m_1, m_2, \dots, m_k$ เป็นจำนวนเต็มบวกที่ coprime เป็นคู่ ๆ และ $M=m_1m_2\cdots m_k$ แล้วระบบ $$x\equiv a_1 \pmod{m_1},\ \dots,\ x\equiv a_k \pmod{m_k}$$ มีคำตอบ เพียงหนึ่งเดียว ใน $[0, M)$

มุมมองเชิงโครงสร้าง: ฟังก์ชัน $x \mapsto (x \bmod m_1, \dots, x \bmod m_k)$ เป็น bijection (และรักษาการบวก/คูณ) ระหว่าง $\mathbb{Z}_M$ กับ $\mathbb{Z}_{m_1}\times\cdots\times\mathbb{Z}_{m_k}$ แปลว่าเราจะ "แยก" ปัญหา mod $M$ เป็นหลาย ๆ ปัญหา mod เล็ก ๆ คำนวณแยกกัน แล้วค่อย "ประกอบ" กลับก็ได้ นี่คือหัวใจของการประยุกต์เกือบทั้งหมด

การสร้างคำตอบแบบตรง (constructive)

ให้ $M_i = M/m_i$ และ $N_i = M_i^{-1} \bmod m_i$ (มีเพราะ coprime) แล้ว

$$x = \sum_{i=1}^{k} a_i M_i N_i \pmod M$$

ตรวจสอบ: เมื่อ mod $m_j$ ทุกพจน์ $i\ne j$ หายไปเพราะ $m_j \mid M_i$ เหลือ $a_j M_j N_j \equiv a_j$

ลองกับตัวอย่าง Sunzi

$M=105$, $M_1=35,\ M_2=21,\ M_3=15$

$N_1 = 35^{-1} \bmod 3 = 2^{-1} \bmod 3 = 2$, $N_2 = 21^{-1} \bmod 5 = 1^{-1} = 1$, $N_3 = 15^{-1}\bmod 7 = 1^{-1}=1$

$x = 2\cdot35\cdot2 + 3\cdot21\cdot1 + 2\cdot15\cdot1 = 140+63+30 = 233 \equiv 23 \pmod{105}$ ✓

ข้อจำกัด สูตรนี้ต้องคำนวณกับค่า $M$ ทั้งก้อน ถ้า $M$ ใหญ่เกิน 64 บิตจะ overflow และใช้ไม่ได้ถ้า modulus ไม่ coprime ในทางปฏิบัติจึงนิยม รวมทีละสองสมการ หรือใช้ Garner

2.2 รวมสองสมการ (วิธีที่ใช้จริงในการแข่ง)

ต้องการ $x$ ที่ $x\equiv a_1 \pmod{m_1}$ และ $x \equiv a_2 \pmod{m_2}$

จากสมการแรก $x = a_1 + m_1 t$ แทนในสมการที่สอง:

$$m_1 t \equiv a_2 - a_1 \pmod{m_2}$$

นี่คือ linear congruence! ให้ $g=\gcd(m_1,m_2)$ และหา $p$ จาก exgcd ที่ $m_1 p + m_2 q = g$

  • ถ้า $g \nmid (a_2-a_1)$ ⇒ ระบบ ไม่มีคำตอบ
  • ไม่อย่างนั้น $t \equiv \frac{a_2-a_1}{g}\cdot p \pmod{\frac{m_2}{g}}$ และ $x \equiv a_1 + m_1 t \pmod{\operatorname{lcm}(m_1,m_2)}$

ทำซ้ำไปเรื่อย ๆ: รวมสมการที่ 1 กับ 2 ได้สมการใหม่ แล้วรวมกับสมการที่ 3 ...

2.3 โค้ด CRT ทั่วไป (รองรับ modulus ที่ไม่ coprime)

// คืน {x, L} โดย x ≡ r[i] (mod m[i]) ทุก i และ L = lcm(m) ; ถ้าไม่มีคำตอบคืน {-1, -1}
// ต้องการให้ lcm ไม่เกิน ~9e18
pair<ll, ll> crt(const vector<ll>& r, const vector<ll>& m) {
    ll R = 0, M = 1;                          // เริ่มจาก x ≡ 0 (mod 1)
    for (size_t i = 0; i < r.size(); i++) {
        ll mi = m[i], ri = ((r[i] % mi) + mi) % mi;
        ll p, q;
        ll g = exgcd(M, mi, p, q);                // M*p + mi*q = g
        if ((ri - R) % g != 0) return {-1, -1};
        ll mg = mi / g;
        ll t = (ll)((__int128)((ri - R) / g) * p % mg);
        if (t < 0) t += mg;
        R += M * t;                               // R ใหม่ยัง < lcm
        M *= mg;                                  // M = lcm(M, mi)
        R %= M;
    }
    return {R, M};
}

ตัวอย่าง: crt({2,3,2},{3,5,7}) → {23, 105}, crt({1,3},{4,6}) → {9, 12}, crt({1,2},{4,6}) → ไม่มีคำตอบ (เพราะ $1\not\equiv 2 \pmod 2$)

เงื่อนไขมีคำตอบ ระบบทั่วไปมีคำตอบก็ต่อเมื่อ $a_i \equiv a_j \pmod{\gcd(m_i, m_j)}$ ทุกคู่ $i,j$ และคำตอบจะไม่ซ้ำ mod $\operatorname{lcm}(m_1,\dots,m_k)$ ใน AtCoder Library ใช้ atcoder::crt(r, m) ได้เลย

2.4 Garner's algorithm (เมื่อคำตอบใหญ่เกิน 64 บิต)

ตามที่ cp-algorithms อธิบาย ถ้า $m_1,\dots,m_k$ coprime เป็นคู่ ๆ เราเขียน $x$ ในรูป mixed radix ได้

$$x = x_1 + x_2 m_1 + x_3 m_1 m_2 + \dots + x_k m_1 \cdots m_{k-1},\qquad 0 \le x_i < m_i$$

หา $x_i$ ทีละตัว: mod $m_2$ ทั้งสองข้างได้ $a_2 \equiv x_1 + x_2 m_1$ ⇒ $x_2 \equiv (a_2 - x_1)\, m_1^{-1} \pmod{m_2}$ ทำแบบเดียวกันต่อไป โดยให้ $r_{ji} = m_j^{-1} \bmod m_i$

// a[i] = x mod p[i], p coprime เป็นคู่ ๆ  →  คืน x mod MOD (MOD อะไรก็ได้)
ll garner(vector<ll> a, vector<ll> p, ll MOD) {
    int k = a.size();
    vector<ll> x(k);
    for (int i = 0; i < k; i++) {
        x[i] = a[i];
        for (int j = 0; j < i; j++) {
            x[i] = inv_mod(p[j], p[i]) * (x[i] - x[j]) % p[i];  // ควร precompute r[j][i]
            if (x[i] < 0) x[i] += p[i];
        }
    }
    ll res = 0, mul = 1;                      // ประกอบกลับแบบ mod MOD
    for (int i = 0; i < k; i++) {
        res = (res + x[i] % MOD * mul) % MOD;
        mul = mul * (p[i] % MOD) % MOD;
    }
    return res;
}

จุดเด่น: ไม่เคยต้องเก็บ $M$ ทั้งก้อน ทุกการคำนวณอยู่ภายใต้ mod $p_i$ เล็ก ๆ ความซับซ้อน $O(k^2)$ และสามารถประกอบเป็นเลขใหญ่ (big integer) หรือเอาเฉพาะ mod ที่ต้องการก็ได้ — นี่คือวิธีที่ใช้ใน NTT แบบ 3 primes เพื่อให้ได้ผล convolution mod ค่าใดก็ได้ (เช่น $10^9+7$)

cp-algorithms ยังชี้ว่าถ้าเรียงค่า mixed radix เราสามารถ เปรียบเทียบ เลขใหญ่สองตัวที่เก็บในรูปเศษได้ด้วย (เทียบจาก $x_k$ ลงมา)

2.5 การประยุกต์ใช้ CRT

สถานการณ์ใช้ CRT อย่างไร
หาเวลาที่สองเหตุการณ์ที่เป็นคาบ "บังเอิญตรงกัน"เหตุการณ์ A เกิดที่ $t\equiv a \pmod p$, B ที่ $t\equiv b\pmod q$ → รวมสองสมการ (เช่น ABC193 E)
$\binom{n}{k} \bmod m$ ที่ $m$ ไม่ใช่จำนวนเฉพาะแยก $m=\prod p_i^{e_i}$ คำนวณ mod $p_i^{e_i}$ แต่ละตัว (Lucas / Granville) แล้วรวมด้วย CRT
convolution mod ค่าใดก็ได้ทำ NTT 3 ครั้งด้วย prime ที่เป็นมิตรกับ NTT แล้ว Garner รวม
คำนวณเลขใหญ่มากแต่รู้ขอบเขตคำนวณ mod หลาย ๆ prime แล้วประกอบ (เช่น determinant ของ matrix จำนวนเต็ม)
Hashing ด้วยสอง modulusคู่ (h mod p, h mod q) เทียบเท่า h mod pq ตาม CRT ⇒ โอกาสชนลดลงเหมือนใช้ mod ใหญ่
ฟังก์ชัน multiplicative ($\varphi$, จำนวนรากของ $x^2\equiv1$)CRT ทำให้นับแยกต่อ prime power แล้วคูณกัน

3Floor sum

3.1 นิยามและภาพเรขาคณิต

ปัญหา กำหนด $n, m, a, b$ ให้หา $$f(n,m,a,b)=\sum_{i=0}^{n-1}\left\lfloor \frac{a i+b}{m} \right\rfloor$$ โดย $n, m$ อาจใหญ่ถึง $10^9$ (ไล่ลูปตรง ๆ ไม่ได้) — ทำได้ใน $O(\log m)$ คล้าย Euclid

ภาพในหัว: ค่า $\lfloor (ai+b)/m \rfloor$ คือจำนวนจุด lattice $(i, j)$ ที่ $1 \le j \le \frac{ai+b}{m}$ ดังนั้น $f$ คือจำนวนจุดจำนวนเต็มที่อยู่ ใต้เส้นตรง $y=\frac{ax+b}{m}$ เหนือแกน x ในช่วง $0\le x

$f(4,10,6,3)$: ค่าในแต่ละ $i=0..3$ คือ $0,0,1,2$ รวม = 3 จุด (จุดสีเขียว)

3.2 การพิสูจน์: ลดรูปแบบ Euclid

ขั้นที่ 1: ลด $a$ และ $b$ ให้เล็กกว่า $m$

ถ้า $a \ge m$ เขียน $a = qm + a'$:

$$\left\lfloor\frac{ai+b}{m}\right\rfloor = qi + \left\lfloor\frac{a'i+b}{m}\right\rfloor \;\Rightarrow\; f(n,m,a,b) = q\cdot\frac{n(n-1)}{2} + f(n,m,a',b)$$

ถ้า $b \ge m$ เขียน $b = q'm + b'$: $\;f(n,m,a,b) = q'\cdot n + f(n,m,a,b')$

ขั้นที่ 2: เมื่อ $a

นับจุดเดิมแต่นับ "ตามแถว" แทน "ตามคอลัมน์" จุด $(i,j)$ ถูกนับเมื่อ $0\le i

สำหรับแต่ละแถว $j$ จำนวน $i$ ที่ใช้ได้คือ

$$n - \left\lceil \frac{jm-b}{a} \right\rceil = \left\lfloor \frac{an + b - jm}{a} \right\rfloor$$

โดย $j$ วิ่งตั้งแต่ $1$ ถึง $n' = \left\lfloor \frac{an+b}{m} \right\rfloor$ ให้ $y_{\max} = an+b$ และ $b' = y_{\max} \bmod m$ แทน $j = n' - k$ ($k=0..n'-1$):

$$an+b-jm = (y_{\max} - n'm) + km = b' + km$$ $$\boxed{\,f(n,m,a,b) = f\!\left(n',\ a,\ m,\ b'\right)\,}$$

สังเกตว่า $m$ กับ $a$ สลับที่กัน — เหมือน $\gcd(m,a) \to \gcd(a, m \bmod a)$ ในขั้นถัดไปจะ mod $m$ ด้วย $a$ จึงจบใน $O(\log \min(a,m))$ รอบ

เงื่อนไขหยุด: ถ้า $y_{\max} < m$ แปลว่าทุกพจน์เป็น 0 แล้ว

3.3 โค้ด (ตาม AtCoder Library)

using ull = unsigned long long;
// sum_{i=0}^{n-1} floor((a*i + b) / m),  ทุกตัว ≥ 0
ull floor_sum_unsigned(ull n, ull m, ull a, ull b) {
    ull ans = 0;
    while (true) {
        if (a >= m) { ans += n * (n - 1) / 2 * (a / m); a %= m; }
        if (b >= m) { ans += n * (b / m); b %= m; }
        ull y_max = a * n + b;
        if (y_max < m) break;
        n = y_max / m;
        b = y_max % m;
        swap(m, a);
    }
    return ans;
}
// รองรับ a, b ติดลบ (floor แบบคณิตศาสตร์) ; 0 ≤ n, 1 ≤ m
ll floor_sum(ll n, ll m, ll a, ll b) {
    ull ans = 0;
    if (a < 0) { ull a2 = ((a % m) + m) % m; ans -= 1ULL * n * (n - 1) / 2 * ((a2 - a) / m); a = a2; }
    if (b < 0) { ull b2 = ((b % m) + m) % m; ans -= 1ULL * n * ((b2 - b) / m); b = b2; }
    return ans + floor_sum_unsigned(n, m, a, b);
}
ขอบเขต ACL รับประกันเมื่อ $n, m \le 10^9$ (คำตอบอาจล้น ll ได้ถ้าใหญ่กว่านี้ ระบบใช้ unsigned เพื่อให้ overflow ระหว่างทาง "วนกลับ" อย่างถูกต้องเมื่อคำตอบสุดท้ายพอดี) ถ้าต้องการผล mod $p$ ให้แก้เป็นคำนวณ mod ทุกขั้น

3.4 เทคนิคแปลงโจทย์ให้เป็น floor sum

(ก) ผลรวมเศษ

$$\sum_{i=0}^{n-1} (ai+b) \bmod m = \sum_{i=0}^{n-1}(ai+b) \;-\; m\cdot f(n,m,a,b)$$

เพราะ $x \bmod m = x - m\lfloor x/m \rfloor$

(ข) นับว่ามีกี่ $i$ ที่ $(ai+b) \bmod m \ge c$

สังเกตว่า $\left\lfloor \frac{x + (m-c)}{m} \right\rfloor - \left\lfloor \frac{x}{m} \right\rfloor$ เป็น 1 ก็ต่อเมื่อ $x \bmod m \ge c$ (เป็น 0 อย่างอื่น) ดังนั้น

$$\#\{\,i : (ai+b)\bmod m \ge c\,\} = f(n,m,a,b+m-c) - f(n,m,a,b)$$

ใช้ได้กับคำถามแนว "นับ $x\in[L,R]$ ที่ $ax \bmod m$ ตกในช่วง $[lo,hi]$" (ลบสองครั้ง)

(ค) บิตที่ k ของ $ai+b$

$$\text{bit}_k(x) = \left\lfloor \frac{x}{2^k} \right\rfloor - 2\left\lfloor \frac{x}{2^{k+1}} \right\rfloor$$

ดังนั้น $\sum_i \text{popcount}(ai+b) = \sum_k \big[f(n,2^k,a,b) - 2f(n,2^{k+1},a,b)\big]$ — ทริกนี้คือแกนของ ABC283 Ex

(ง) นับจุด lattice ใต้เส้นตรง / ในรูปสามเหลี่ยม

จำนวนคู่ $(x,y)$ จำนวนเต็มไม่ติดลบที่ $px + qy \le r$ คือ $\sum_{x=0}^{\lfloor r/p\rfloor} \left(\left\lfloor\frac{r - px}{q}\right\rfloor + 1\right)$ ซึ่งเป็น floor sum ที่มี $a=-p$ (ใช้เวอร์ชันที่รองรับค่าติดลบ)

(จ) จำนวน $i$ ที่ $\lfloor (ai+b)/m \rfloor$ เปลี่ยนค่า, ผลรวมแบบ $\sum \lfloor i\cdot\alpha \rfloor$ เมื่อ $\alpha$ เป็นเศษส่วน

ทุกอย่างที่มีหน้าตา "floor ของฟังก์ชันเชิงเส้นของ $i$" ให้นึกถึง floor sum ก่อนเสมอ

    ll n2 = N / g;

5.2 Template: modint + nCr

แทนที่จะเขียน % MOD ทุกบรรทัด (ซึ่งลืมง่ายมาก) ให้ห่อตัวเลขไว้ใน struct ที่ mod ให้อัตโนมัติ เป็นสิ่งที่นักแข่งระดับสูงเกือบทุกคนใช้

template<int MOD> struct Mint {
    int v;
    Mint(ll x = 0) { x %= MOD; if (x < 0) x += MOD; v = x; }
    Mint& operator+=(Mint o) { if ((v += o.v) >= MOD) v -= MOD; return *this; }
    Mint& operator-=(Mint o) { if ((v -= o.v) < 0) v += MOD; return *this; }
    Mint& operator*=(Mint o) { v = (ll)v * o.v % MOD; return *this; }
    Mint pow(ll e) const { Mint r = 1, a = *this; while (e) { if (e & 1) r *= a; a *= a; e >>= 1; } return r; }
    Mint inv() const { return pow(MOD - 2); }             // MOD ต้องเป็นจำนวนเฉพาะ
    Mint& operator/=(Mint o) { return *this *= o.inv(); }
    friend Mint operator+(Mint a, Mint b) { return a += b; }
    friend Mint operator-(Mint a, Mint b) { return a -= b; }
    friend Mint operator*(Mint a, Mint b) { return a *= b; }
    friend Mint operator/(Mint a, Mint b) { return a /= b; }
    friend ostream& operator<<(ostream& os, Mint a) { return os << a.v; }
};
using mint = Mint<1000000007>;               // หรือ 998244353

const int N = 1000000;
mint fact[N + 1], ifact[N + 1];
void init() {
    fact[0] = 1;
    for (int i = 1; i <= N; i++) fact[i] = fact[i - 1] * i;
    ifact[N] = fact[N].inv();                       // inverse ครั้งเดียว O(log)
    for (int i = N; i > 0; i--) ifact[i - 1] = ifact[i] * i;   // ไล่ย้อนกลับ
}
mint C(int n, int k) {
    if (k < 0 || k > n) return 0;
    return fact[n] * ifact[k] * ifact[n - k];
}

5.3 ความน่าจะเป็น / ค่าคาดหวังภายใต้ mod

Codeforces และ AtCoder ชอบถามค่าคาดหวังที่เป็นเศษส่วน แล้วให้ตอบเป็น $P\cdot Q^{-1} \bmod p$ กฎสำคัญ: ทุกการดำเนินการที่ใช้กับเศษส่วนได้ ใช้กับ modint ได้หมด (บวก ลบ คูณ หาร) เพราะ $\mathbb{Z}_p$ เป็น field ดังนั้นแค่เขียนสูตรตามปกติแล้วใช้ mint แทน double

ตัวอย่าง — Coupon collector

ลูกเต๋ามี $n$ หน้า ($n\le10^6$) ทอยจนกว่าจะเห็นครบทุกหน้า คาดหวังว่าจะทอยกี่ครั้ง? ตอบ mod $10^9+7$

เฉลย

เมื่อเห็นแล้ว $i$ หน้า โอกาสได้หน้าใหม่คือ $\frac{n-i}{n}$ จำนวนครั้งที่คาดหวังจึงเป็น $\frac{n}{n-i}$ (geometric distribution) รวมได้ $E = \sum_{i=1}^{n} \frac{n}{i} = n H_n$

mint coupon(int n) {
    mint s = 0;
    for (int i = 1; i <= n; i++) s += mint(n) / i;   // O(n log p) ; ใช้ inv table ได้ O(n)
    return s;
}
// n = 2 → 3      n = 6 → 14.7 = 147/10 → 900000021

  • DP ความน่าจะเป็นแบบ "ทอยจนกว่า…" มักได้สมการ $E = 1 + pE + \dots$ ให้ย้ายข้างแก้แบบพีชคณิตก่อน แล้วค่อยหาร

5.4 เลขชี้กำลังซ้อน $a^{b^c} \bmod p$

จาก Fermat: ถ้า $p \nmid a$ แล้ว $a^{p-1}\equiv 1$ ดังนั้นเลขชี้กำลังสามารถ mod ด้วย $p-1$ ได้: $a^{b^c} \equiv a^{\,b^c \bmod (p-1)} \pmod p$

CSES 1712 — Exponentiation II
ลิงก์โจทย์
ll tower(ll a, ll b, ll c) {
    const ll P = 1000000007;
    if (a % P == 0)                                  // Fermat ใช้ไม่ได้ ต้องแยกเคส
        return (b == 0 && c > 0) ? 1 : 0;           // b^c == 0 → a^0 = 1
    return binpow(a, binpow(b, c, P - 1), P);        // สังเกต: mod P-1 ไม่ใช่ P
}
กรณี mod ไม่ใช่จำนวนเฉพาะ ใช้ Euler's theorem แบบทั่วไป: ถ้า $e \ge \varphi(m)$ แล้ว $a^e \equiv a^{(e \bmod \varphi(m)) + \varphi(m)} \pmod m$ (ใช้ได้แม้ $\gcd(a,m)\ne 1$) — ใช้กับ power tower $a_1^{a_2^{a_3^{\cdots}}}$ โดยเรียกซ้ำ $m \to \varphi(m) \to \varphi(\varphi(m))\to\dots$ ซึ่งลดลงเป็น 1 ใน $O(\log m)$ ขั้น

5.5 ผลรวมที่มี $\lfloor n/i \rfloor$ — แบ่งบล็อก $O(\sqrt n)$

อย่าสับสนกับ floor sum: ที่นี่ตัวหารเปลี่ยน ($n/i$) ไม่ใช่ฟังก์ชันเชิงเส้น ข้อสังเกตคือ $\lfloor n/i \rfloor$ มีค่าที่ต่างกันไม่เกิน $2\sqrt n$ ค่า และ $i$ ที่ให้ค่าเดียวกัน $q$ เป็นช่วงต่อเนื่อง $[l, r]$ โดย $r = \lfloor n / q \rfloor$

CSES 1082 — Sum of Divisors
ลิงก์โจทย์ · หา $\sum_{i=1}^{n}\sigma(i) \bmod 10^9+7$, $n \le 10^{12}$

สลับลำดับการรวม: ตัวหาร $d$ ปรากฏใน $\lfloor n/d \rfloor$ จำนวน จึงได้ $\sum_{d=1}^{n} d\cdot\lfloor n/d\rfloor$ ในแต่ละบล็อก $[l,r]$ ค่า $\lfloor n/d\rfloor = q$ คงที่ ผลรวม $d$ คือ $\frac{(l+r)(r-l+1)}{2}$ — ต้องหาร 2 ภายใต้ mod จึงต้องใช้ inverse

mint sum_divisors(ll n) {
    mint ans = 0;
    for (ll l = 1, r; l <= n; l = r + 1) {
        ll q = n / l;
        r = n / q;                                     // i สุดท้ายที่ n/i == q
        mint s = mint(l + r) * mint(r - l + 1) / 2;     // mod ก่อนคูณ กัน overflow
        ans += s * q;
    }
    return ans;
}
// n = 5 → 21

5.6 ของที่วนเป็นคาบ / เดินบนวงกลม

สามข้อเท็จจริงที่ควรจำให้ขึ้นใจ:

  1. เริ่มที่ 0 บนวงกลม $N$ ช่อง เดินทีละ $K$ จะไปถึงได้เฉพาะช่องที่เป็น พหุคูณของ $g=\gcd(K,N)$ และกลับมาที่เดิมหลัง $N/g$ ก้าว
  2. "อยู่ช่อง $T$ ได้ครั้งแรกเมื่อไหร่" = แก้ $Kt \equiv T \pmod N$ (ABC186 E)
  3. สองเหตุการณ์ที่มีคาบ $p, q$ จะตรงเฟสกันซ้ำทุก $\operatorname{lcm}(p,q)$ และ "ตรงกันครั้งแรก" คือ CRT (ABC193 E)
มุมมองที่ช่วยได้มาก ถ้าโจทย์จำลองกระบวนการที่วนไปเรื่อย ๆ (สลับตำแหน่ง, หมุน, permutation) ให้แยกเป็น cycle หาคาบของแต่ละ cycle แล้วใช้ CRT/lcm รวม เช่น "permutation ต้องทำซ้ำกี่ครั้งถึงกลับมาเหมือนเดิม" = lcm ของความยาว cycle ทั้งหมด (ระวัง lcm ใหญ่: เก็บเป็นการแยกตัวประกอบเฉพาะ แล้วค่อย mod)

5.7 เมื่อ mod ไม่ใช่จำนวนเฉพาะ หรือใหญ่มาก

ปัญหาวิธีแก้
$m$ ประกอบ ต้องหารinverse มีเฉพาะ $\gcd(a,m)=1$ ใช้ exgcd หรือแยก $m = \prod p_i^{e_i}$ คำนวณแยกแล้ว CRT รวม
$\binom{n}{k} \bmod m$, $m$ ประกอบLucas ต่อ prime + CRT (ตัวอย่าง 6 ในหัวข้อ 4)
$m \approx 10^{18}$คูณด้วย (__int128)a * b % m

5.8 นับ $x\in[L,R]$ ที่ $(ax+b) \bmod m \in [lo, hi]$ — floor sum ในการแข่ง

ฟังก์ชันพร้อมใช้ (ต่อยอดจากเทคนิค (ข) ในหัวข้อ 3.4) ตอบใน $O(\log m)$ แม้ช่วงยาว $10^{18}$:

// จำนวน x ใน [L, R] ที่ (a*x + b) mod m อยู่ใน [lo, hi]   (0 ≤ lo ≤ hi < m)
ll count_range(ll L, ll R, ll a, ll b, ll m, ll lo, ll hi) {
    ll n = R - L + 1;
    a = ((a % m) + m) % m;
    ll b0 = (ll)(((__int128)a * L + b) % m + m) % m;     // แทน x = L + i
    auto ge = [&](ll c) {                                // #{ i : (a*i + b0) mod m >= c }
        return floor_sum(n, m, a, b0 + m - c) - floor_sum(n, m, a, b0);
    };
    return ge(lo) - ge(hi + 1);
}

รูปแบบโจทย์ที่ใช้ได้:

  • "มีกี่วันที่ช่วงเวลาที่ $ax \bmod m$ อยู่ในช่วงทำงาน" (นาฬิกา, ตารางเวลาที่เลื่อนทีละ $a$)
  • "มีกี่ $x$ ที่บิตที่ $k$ ของ $ax+b$ เป็น 1" = เศษ mod $2^{k+1}$ อยู่ใน $[2^k, 2^{k+1})$
  • "$\lfloor (ax+b)/m \rfloor$ เป็นเลขคู่กี่ตัว" = เศษ mod $2m$ อยู่ใน $[0, m)$
  • ใช้เป็น oracle ใน binary search: "หา $x$ น้อยสุดที่มีตัวที่เศษ $\le c$ อย่างน้อย $k$ ตัว"

5.9 Checklist ก่อนกดส่ง

  • ☐ ทุกการลบ: บวก MOD กลับก่อน mod แล้วหรือยัง (หรือใช้ modint)
  • ☐ คูณสองค่าที่ mod แล้ว: ใช้ long long (MOD ~1e9) หรือ __int128 (MOD ~1e18)
  • ☐ Input ใหญ่ถึง $10^{18}$: mod ก่อนเอาไปคูณ (mint(l + r) ไม่ใช่ mint((l + r) * (r - l + 1)))
  • ☐ หาร: ตัวหารเป็น 0 mod p ได้หรือไม่? MOD เป็นจำนวนเฉพาะจริงหรือไม่?
  • ☐ เลขชี้กำลัง: mod ด้วย $p-1$ ไม่ใช่ $p$ และระวังเคส $a \equiv 0$
  • ☐ CRT: lcm พอดี 64 บิตหรือไม่? ถ้าไม่ ใช้ Garner หรือตรวจ overflow
  • ☐ floor sum: ข้อจำกัด $n, m \le 10^9$; ถ้า $a, b$ ติดลบใช้เวอร์ชันที่รองรับ
  • ☐ คำตอบสุดท้ายเป็นค่าใน $[0, \text{MOD})$ ไม่ใช่ค่าติดลบ
